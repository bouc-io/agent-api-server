```
                                                    │
                                                    ▼
                                            ┌─────────────────┐
                                            │  Sandbox Envs   │
```

### Execution System Implementation

#### Worker Process Flow

```python
# Pseudocode for agent executor worker

while True:
    message = message_queue.get()
    
    cycle = AgentCycle(
        assignment_id=message.assignment_id,
        max_iterations=10
    )
    
    for iteration in range(cycle.max_iterations):
        # 1. Agent reasoning
        response = llm.generate(
            conversation_history=get_messages(assignment_id),
            tools=get_enabled_tools(),
            system_prompt=get_system_prompt()
        )
        
        # 2. Parse agent decision
        if response.is_final_answer():
            cycle.complete(response.content)
            break
        
        if response.has_tool_call():
            # 3. Execute tool
            tool_result = execute_tool(
                tool_name=response.tool_name,
                tool_input=response.tool_input,
                sandbox_id=cycle.sandbox_id
            )
            
            # 4. Store observation
            cycle.add_iteration(
                reasoning=response.reasoning,
                action=response.tool_call,
                observation=tool_result
            )
            
            # 5. Continue to next iteration
            continue
    
    # Save final result
    save_cycle_result(cycle)
    notify_client(cycle)
```

### Integration with REST API

#### Message Creation with Agent Execution

When a user sends a message, the flow is:

1. **REST API receives message** → Saves to database
2. **Publishes to message queue** → `{assignment_id, message_id}`
3. **Worker picks up job** → Starts agent cycle
4. **Agent iterates** → Uses tools, executes code
5. **Worker streams updates** → Via WebSocket or SSE
6. **Completion** → Saves assistant message, notifies client

#### Client Integration Example

```javascript
// Client creates message
const response = await fetch('/v1/assignments/123/messages', {
  method: 'POST',
  body: JSON.stringify({
    content: 'Analyze this dataset'
  })
});

const { cycle_id } = await response.json();

// Stream agent progress
const eventSource = new EventSource(
  `/v1/agent/cycles/${cycle_id}/stream`
);

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  
  if (data.type === 'iteration_start') {
    console.log('Agent thinking:', data.reasoning);
  } else if (data.type === 'output') {
    console.log('Output:', data.content);
  } else if (data.type === 'cycle_complete') {
    console.log('Done:', data.final_result);
    eventSource.close();
  }
};
```

### Execution Database Schema

```sql
-- Execution cycles
CREATE TABLE agent_cycles (
    id UUID PRIMARY KEY,
    assignment_id UUID REFERENCES assignments(id),
    status VARCHAR(20),
    current_iteration INT,
    max_iterations INT,
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    final_result JSONB
);

-- Individual iterations within a cycle
CREATE TABLE cycle_iterations (
    id UUID PRIMARY KEY,
    cycle_id UUID REFERENCES agent_cycles(id),
    iteration_number INT,
    reasoning TEXT,
    action JSONB,
    observation TEXT,
    started_at TIMESTAMP,
    completed_at TIMESTAMP
);

-- Code executions
CREATE TABLE executions (
    id UUID PRIMARY KEY,
    cycle_iteration_id UUID REFERENCES cycle_iterations(id),
    assignment_id UUID REFERENCES assignments(id),
    language VARCHAR(50),
    code TEXT,
    status VARCHAR(20),
    output TEXT,
    error TEXT,
    exit_code INT,
    sandbox_id UUID,
    created_at TIMESTAMP,
    started_at TIMESTAMP,
    completed_at TIMESTAMP
);

-- Sandboxes
CREATE TABLE sandboxes (
    id UUID PRIMARY KEY,
    assignment_id UUID REFERENCES assignments(id),
    container_id VARCHAR(255),
    language VARCHAR(50),
    status VARCHAR(20),
    created_at TIMESTAMP,
    expires_at TIMESTAMP
);
```

**Request body:**

**Relation types:**
- `related_to`: General relation
- `contradicts`: Conflicting information
- `supersedes`: Newer info replaces old

### Memory Database Schema

```sql
-- Core memories table
CREATE TABLE memories (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    content TEXT NOT NULL,
    type VARCHAR(50) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    access_count INT DEFAULT 0,
    last_accessed_at TIMESTAMP,
    metadata JSONB,
    embedding_id VARCHAR(255),
    CONSTRAINT valid_memory_type CHECK (type IN (
        'preference', 'fact', 'skill', 'goal', 
        'context', 'instruction', 'entity', 'relationship'
    ))
);

-- Memory tags (many-to-many)
CREATE TABLE memory_tags (
    memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    tag VARCHAR(100),
    PRIMARY KEY (memory_id, tag)
);

-- Memory sources (link to assignments/messages)
CREATE TABLE memory_sources (
    id UUID PRIMARY KEY,
    memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    source_type VARCHAR(50), -- 'assignment', 'message', 'manual'
    source_id UUID,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Memory relations (graph)
CREATE TABLE memory_relations (
    id UUID PRIMARY KEY,
    source_memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    target_memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    relation_type VARCHAR(50) NOT NULL,
    strength FLOAT DEFAULT 1.0,
    metadata JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    CONSTRAINT no_self_relation CHECK (source_memory_id != target_memory_id)
);

-- Memory collections
CREATE TABLE memory_collections (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    name VARCHAR(255) NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Collection memberships
CREATE TABLE collection_memories (
    collection_id UUID REFERENCES memory_collections(id) ON DELETE CASCADE,
    memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    added_at TIMESTAMP DEFAULT NOW(),
    PRIMARY KEY (collection_id, memory_id)
);

-- Memory extraction jobs
CREATE TABLE memory_extractions (
    id UUID PRIMARY KEY,
    assignment_id UUID REFERENCES assignments(id),
    status VARCHAR(50),
    extracted_count INT,
    created_at TIMESTAMP DEFAULT NOW(),
    completed_at TIMESTAMP,
    metadata JSONB
);

-- Memory access log (for analytics)
CREATE TABLE memory_access_log (
    id UUID PRIMARY KEY,
    memory_id UUID REFERENCES memories(id) ON DELETE CASCADE,
    assignment_id UUID REFERENCES assignments(id),
    accessed_at TIMESTAMP DEFAULT NOW(),
    relevance_score FLOAT
);

-- Indexes for performance
CREATE INDEX idx_memories_user_type ON memories(user_id, type);
CREATE INDEX idx_memories_created_at ON memories(created_at DESC);
CREATE INDEX idx_memories_embedding ON memories(embedding_id);
CREATE INDEX idx_memory_tags_tag ON memory_tags(tag);
CREATE INDEX idx_memory_sources_source ON memory_sources(source_type, source_id);
CREATE INDEX idx_memory_relations_source ON memory_relations(source_memory_id);
CREATE INDEX idx_memory_relations_target ON memory_relations(target_memory_id);
```

### Memory System Implementation Notes

#### Vector Database Integration

Use a vector database for semantic search:
- **Pinecone**: Managed, easy to use
- **Weaviate**: Open-source, feature-rich
- **Qdrant**: Fast, Rust-based
- **pgvector**: PostgreSQL extension

Example integration:
```python
# When creating a memory
embedding = generate_embedding(memory.content)
vector_db.upsert(
    id=memory.id,
    vector=embedding,
    metadata={
        "type": memory.type,
        "tags": memory.tags,
        "created_at": memory.created_at
    }
)

# When searching
query_embedding = generate_embedding(search_query)
results = vector_db.search(
    vector=query_embedding,
    limit=10,
    filter={"type": {"$in": ["preference", "skill"]}}
)
```

#### Memory Retrieval Strategy

When processing a new message in an assignment:

1. **Extract context** from recent messages
2. **Query vector DB** with context embedding
3. **Filter and rank** by relevance + recency + access count
4. **Inject top N memories** into system prompt
5. **Log access** for analytics

#### Automatic Memory Extraction

Run extraction after conversations using LLM:
```python
extraction_prompt = """
Analyze this conversation and extract:
1. User preferences (likes, dislikes, preferred tools)
2. User skills and expertise
3. Important facts about the user or their context
4. Long-term goals mentioned

For each item, provide:
- Content (the actual memory)
- Type (preference/skill/fact/goal)
- Confidence (0-1)
"""
```

#### Memory Consolidation

Periodically merge or update duplicate/related memories:
- Detect similar embeddings (cosine similarity > 0.95)
- Merge content or mark as superseding
- Update relations accordingly
